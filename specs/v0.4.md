# Phiên bản v0.4.0 (Tiến tới v1.0.0 Enterprise)

## Mục tiêu (Goal)

Hoàn thiện hệ sinh thái `speckit-ai` bằng việc bổ sung khả năng kiểm soát chất lượng tài liệu (Linter) và nâng cao trải nghiệm đọc tài liệu cho team Non-Tech (Docs Website).

## Tính năng sẽ triển khai (Features)

### Phase 1: Spec Linter (Bảo vệ tính toàn vẹn của Spec)

- **Mô tả:** Lệnh `npx speckit-ai lint` sẽ quét thư mục `specs/` và `docs/`.
- **Cơ chế:** So khớp cấu trúc của các file Markdown hiện tại với các headers (`##`) có trong file template gốc.
- **Use case:** Ngăn chặn việc Dev tạo file Spec nhưng xóa mất các mục quan trọng như `Security`, `Edge Cases` hay `Data Models`. Có thể tích hợp Linter này vào chính Git Hook hiện tại để cấm commit nếu Spec viết thiếu mục.

### Phase 2: Docs as a Website (Static Site Generator)

- **Mô tả:** Cung cấp lệnh `npx speckit-ai serve` và `npx speckit-ai build`.
- **Cơ chế:** Tự động gom toàn bộ các file markdown trong `docs/` và `specs/`, dựng thành một trang web giao diện đẹp mắt, có Sidebar phân cấp thư mục, có chức năng tìm kiếm (Search) và Dark mode.
- **Use case:** Giúp sếp, BA, Tester có một cổng thông tin (Portal) duy nhất để vào đọc tài liệu thiết kế của dự án mà không cần mở Github hay IDE.

## Lộ trình (Roadmap)

- [ ] Thiết kế cơ chế phân tích Markdown (AST Parser / Regex) cho Linter.
- [ ] Tích hợp `speckit-ai lint` vào hệ thống CLI commands.
- [ ] Tích hợp Linter vào Git pre-commit hook.
- [ ] Lựa chọn engine (như VitePress hoặc tự build engine nhẹ bằng Express + Marked) cho lệnh `serve`.
- [ ] Chạy thử nghiệm và release v0.4.0.
